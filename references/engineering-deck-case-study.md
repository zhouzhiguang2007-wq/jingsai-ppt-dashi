# 29 页工程竞赛答辩稿的版式与叙事拆解

依据用户提供的一份 29 页、16:9 的浅蓝工程竞赛 PPTX 逐页渲染、检查原生对象后整理。它是**参考案例**，不是事实来源或固定模板。后续制稿只复用能解释信息关系的结构和设计规律；不移植其中的工程照片、人物、论文专利、政策、数字和项目结论，也不把本案例的页数和颜色强加给其他比赛。

## 整套稿的骨架

1. **立题（1–6）**：封面建立项目识别；事故证据、实地调研、痛点对应、政策与战略场景依次回答“为什么做”。事实证据和远期愿景分开陈述。
2. **方法（7–12）**：一页三模块总览，随后按“问题证据 → 方法步骤 → 对照或结果”解释少标签训练、长短时序融合和原型分类。读者先看全链路，再看每条创新点。
3. **证明（13–15）**：论文、专利与奖项集中展示；工程案例用大图、工况、关键方法和可核查指标说明应用。须区分本项目验证、团队既有成果和合作项目成果。
4. **落地（16–21）**：行业资料与采购条件、竞品矩阵、分阶段商业服务、公司筹备、财务测算、融资与股权。已完成、试点中、预计和待触发的状态分明。
5. **人和价值（22–29）**：负责人、成员、顾问、产教协同、社会价值、可验收的下一步，最后以封面母题收束。

整稿使用浅蓝隧道/海底底纹，顶部“章节标题＋短副标题＋校徽”作为导航；深蓝 `#0E419C` 与亮蓝 `#2978F7` 是主要色，青色辅助数据关系，橙/黄/红只在关键差异、指标或风险处出现。多数正文页用蓝色底部结论带做一页一重点。画面中有原生形状、线、表格、图表和实拍/证据图混用；这些对象要按内容意义选择，不能把所有页面强行改成统一卡片。

## 逐页借鉴点

| 页 | 这页承担的任务与形式 | 可复用的判断 |
|---|---|---|
| 1 | 巨幅项目名、核心设备主视觉、短副标题、学校标识 | 封面用一个强视觉锚点说明领域；标题与机器图互相让位，避免堆满项目介绍。 |
| 2 | 四个事故案例并列，包含地点/时间、图、后果数字与底部结论 | 风险页让案例可比较；标清“背景事故”与“本技术已验证能防范”的边界，保留来源。 |
| 3 | 三个时间节点的实地调研，配现场/线路图和地点标签 | 用时间轴证明需求来自现场；正在进行或未来节点必须标状态，地点占位词不得伪装为事实。 |
| 4 | 三组痛点各以大箭头指向对应技术，右侧方法解释 | 先一对一映射“问题→方法”，再给技术细节；箭头表示真正的因果/解决关系。 |
| 5 | 国家与地方政策文件的主次拼贴，底部概括 | 政策页应突出与项目直接相关的条文和时间，不用大量缩小的文件截图代替证据。 |
| 6 | 隧道场景图＋三项工程挑战＋战略意义 | 用场景解释研究的外部意义；规划、推测和已建事实分层标注，未经证实的效果数字不作结论。 |
| 7 | 三列技术模块：证据图、短说明、串联流程带 | 总览页固定模块名称和顺序，后面分章节沿用同一命名；流程带把模块关系说清。 |
| 8 | 左侧钻孔/掘进数据证据，右侧方法步骤与对照柱图 | 技术页把“数据不足”和“怎样利用数据”放在同一视野；结果图注明数据集、样本和指标定义。 |
| 9 | 现场采集照片、步骤链、训练示意与预期效果 | 方法步骤用短动词和方向线；预期效果不能写成已达到的实测结果。 |
| 10 | 工程问题现场图、双分支模型结构、传统方法对比、指标强调 | 技术结构与工程问题对应；技术图可读，数值需有试验条件与对照来源。 |
| 11 | 相似地层/跨线问题的照片与地图、传统/新方法两列表 | 对比表先写同一比较维度，再写差异；底部说明迁移适配的前提。 |
| 12 | 现场照片、原型匹配示意和分类对照，形成上一页续篇 | 同一技术点拆两页时沿用标题与表格编码，一页讲原因，一页讲计算/验证，避免重复堆图。 |
| 13 | 论文、专利、奖项、软著四象限证据墙 | 让荣誉与成果可以被核实；每组写清数量、归属、状态和与当前项目的关系。 |
| 14 | 一个工程案例：大幅现场图、工况、核心方法、成果 | 案例页按“现场—条件—采取的技术—效果”组织；合作项目成果不能自动归属于本产品。 |
| 15 | 第二个工程案例：多角度实拍图与三项大数字 | 后续案例沿用相同指标和证据顺序；指标单位、测量口径和来源靠近数字。 |
| 16 | 左侧政策/产业/研究定位，右侧文件证据与商业四问 | 从行业趋势过渡到真实购买条件；需求、数据、适配、采购四个门槛比空泛市场规模更有用。 |
| 17 | 五列竞品矩阵，突出自家方案一行，底部注明资料缺口 | 比较同尺度、同证据级别；公开报价缺失时标“待核实”，不要推导没有依据的优势。 |
| 18 | 服务交付分三阶段，右侧试验结果与验证闭环 | 把技术变成可交付物和验收物；试点边界、风险复核、旁路运行写明，不能暗示直接控制设备。 |
| 19 | 六步公司筹备路线，每步有“已做/待触发”状态 | 未来组织计划可展示，但不制作尚不存在的营业执照、客户或已运营时间线。 |
| 20 | 三年财务表＋关键指标＋柱图＋测算脚注 | 数表与图表必须同源，收入、成本、利润、毛利率、盈亏平衡时间和回收期互相核算。 |
| 21 | 融资用途、股权议题与条款框架 | 把融资额、资金用途、知识产权、激励和退出条件分开；预测与已签约事实要有明显状态。 |
| 22 | 负责人双栏人物页，头像、职能、荣誉分别陈列 | 人物页只保留能证明其承担项目角色的经历与证据，避免照片与奖状重复抢焦点。 |
| 23 | 六人等尺寸成员卡：照片、姓名、职责、专业、经历 | 多人页用一致照片裁切与固定信息字段，让评委比较“谁负责什么”。 |
| 24 | 三位顾问大幅半身像与资历 | 顾问页强调指导领域和与项目关联；肖像、姓名、头衔需核实授权与真实性。 |
| 25 | 学校平台、企业条件、人才与项目产出四区，配工程示意图 | 产教页清楚呈现双方投入与双方收获；示意图不冒充现场照片。 |
| 26 | 校企协作照片矩阵、循环关系与“学校/企业/观众”条件 | 多照片页先按事件归类，再用流程解释接口；避免图片墙挤掉主要结论。 |
| 27 | 科创育人、交流合作、对外传播三列价值页 | 社会价值从可发生的具体活动出发，分别给对象、行动、产出。 |
| 28 | 实验设施照片＋近期/下一步/再推进的分期路线 | 未来规划用“任务、所需数据、验收标准”写，远期适用性由新数据证明。 |
| 29 | 重复封面主视觉与项目口号，简短致谢 | 收尾呼应开场，不再加入新事实；视觉元素可重用，信息量要比封面少。 |

## 抽象成可操作的制稿规则

- **先立证据链，再选页型**：每个章节回答一个评委问题；事故、政策、现场、实验、财务和团队分别用适合其证据的结构。先核对“主张—证据—口径—状态”，再设计颜色与图形。
- **保持母版，但不要机械复制内容区**：固定标题锚点、校徽、浅蓝底纹和少量字色；时间页用轴，方法页用步骤，案例页用现场大图，数字页用同源图表，团队页用标准化身份字段。
- **箭头必须承载关系**：步骤箭头表示先后，比较箭头表示从旧法到新法，反馈环表示验证/迭代。背景装饰线与真实关系线分开，箭头旁写清节点输入/输出。
- **图片分层标注**：实拍、新闻截图、政策文件、模型图、论文图、AI 示意图使用不同的来源标签；裁切保留关键对象，别把小字截图当正文。
- **底部结论带只保留一条可证明的结论**：重复铺满每页或字号过大，会压缩证据空间。正文过密时先拆页、删冗余说明或放大证据，不先缩到难读字号。
- **交付前核算**：特别复核财务页的口径与公式、荣誉数量与主体归属、应用案例的项目关系、预测与实绩状态。本案例中的数字和文案不是可复用事实，不能直接复制到新项目。
